# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Architecture

Rust business logic in `core/` is exposed through four binding generators, each feeding SDKs under `sdks/`:

- `generators/node` (neon) → `sdks/node`
- `generators/wasm` (wasm-bindgen) → `sdks/web`
- `generators/uniffi` (uniffi 0.28.3) → `sdks/go`, `sdks/python`, `sdks/kotlin`
- `generators/c_bind` (safer-ffi) → `sdks/php`

`cli/` is deprecated. The README and `docs/` are written in Portuguese; code and comments are in English.

## Commands

The root `Makefile` is the source of truth. Build an SDK with `make build-<node|wasm|go|python|kotlin|php>-sdk`. Go and PHP also have `-linux` variants that skip the Windows cross-build.

- Every full build cross-compiles to `x86_64-pc-windows-gnu`, so it needs mingw-w64 and that rustup target (`make install-deps`).
- `make test` runs `make clean` first. That deletes all generated SDK artefacts and the Go module cache, then rebuilds and tests everything. It is slow.
- Core features are `simple` and `iterative` (`iterative` is the default and is what the SDKs ship). **Never use `cargo ... --all-features`**: both features define `const P`, so it won't compile.
- Kotlin tests only run with `./gradlew test -PrunTests`. Without the flag they are silently skipped.
- Node SDK tests need `sdks/node/native/index.node`, which is gitignored. Run `make build-node-sdk` first.
- In `generators/wasm`, `npm test` overwrites `generators/wasm/pkg` with nodejs-target builds. Only `make build-wasm-sdk` produces `sdks/web/pkg`.
- Python tests: `cd sdks/python && python3 -m unittest discover -s tests -p "*.py"`.
- Rust changes must be clean under `cargo fmt` and `cargo clippy`. CI runs `cargo fmt --all --check` and `cargo clippy --workspace --all-targets -- -D warnings`.

## Generated code: regenerate, don't hand-edit

Generated bindings **and native binaries are committed**. CI for Go, Python, PHP and Kotlin tests the committed files without rebuilding Rust. After any Rust change, run the matching `make build-*-sdk` for every affected SDK and commit the output.

Generated files:
- Go: `sdks/go/internal/payment_plan_uniffi/*`, `sdks/go/internal/libs/**`
- Python: `sdks/python/payment_plan/_internal/*`
- Kotlin: `sdks/kotlin/src/main/kotlin/.../internal/payment_plan_uniffi.kt`, `sdks/kotlin/src/main/resources/native/**`
  - The Makefile seds this file to `internal` visibility.
- PHP: `sdks/php/src/Internal/native/*`
  - The Makefile strips the `__cplusplus` guards from the header, because PHP `FFI::cdef` can't parse them.
- Web: `sdks/web/pkg/*`
- Node: `sdks/node/types/**` (generated by `npm run build` from the JSDoc in `src/index.js`)

UniFFI bindings embed API checksums. A binding and a binary from different builds fail with "UniFFI API checksum mismatch". Always regenerate them together with `make`.

## Adding a public function (all SDKs, same PR)

Every SDK gets the function and a test. Web Playwright coverage is optional. Commit roughly one commit per layer, in this order:

1. `core/src/lib.rs`: public wrapper; put the logic in a module.
2. `generators/c_bind/src/lib.rs`: `#[ffi_export]` with an out-pointer result, returning a `PaymentPlanResult` status. Dates are `i64` Unix millis. `///` doc comments end up in the C header.
3. `generators/node/src/lib.rs`: neon function, registered with a camelCase name in `#[neon::main]`.
4. `generators/uniffi/src/lib.rs`: `#[uniffi::export]`, placed above `uniffi::setup_scaffolding!()`. Dates are `SystemTime`.
5. `generators/wasm/src/lib.rs`: `#[wasm_bindgen(js_name = "camelCase")]`, plus a spec in `generators/wasm/test/iterative/`.
6. For each SDK: run `make build-*-sdk`, then edit the hand-written wrapper and add a test.
   - Go: `sdks/go/lib.go`, test in `lib_test.go`.
   - Kotlin: `PaymentPlan.kt` (`@JvmStatic` + KDoc), test in `PaymentPlanTest.kt`.
   - Node: `sdks/node/src/index.js` (JSDoc + `module.exports`), then `npm run build`; test in `test/*.spec.mjs`.
   - PHP: `src/Internal/FFIPaymentPlan.php` and `src/PaymentPlan.php`; test in `tests/PaymentPlanTest.php`.
   - Python: `payment_plan/__init__.py` (wrapper + `__all__`); test in `tests/test_payment_plan.py`.
7. Bump the version by hand in `generators/node/package.json`, `generators/wasm/package.json` and `sdks/node/package.json`, keeping all three in sync. The other SDK versions come from the release tag.

New `Params` fields touch the param conversion in every generator (`c_bind/src/params.rs`, `node/src/cast.rs`, `uniffi/src/params.rs`, `wasm/src/types/param.rs`) and each SDK's Params types.

There is no shared fixture file. Every SDK's tests duplicate the same scenarios and expected values, so keep them consistent across languages.

## Gotchas

- Dates: every binding converts an input to a date through **UTC**. Output dates are given fixed hours aimed at Brazil (UTC-3); for example, Node uses 03:00 UTC.
- `next_disbursement_date` depends on `chrono::Local::now()`.
- `core/src/util.rs` `BRAZILIAN_BANK_HOLIDAYS` is a fixed-length array searched with `binary_search`. It must stay sorted, and its length must be updated when entries are added.
- Money values are `f64`. Percentages are 0.0–1.0, except `debit_service_percentage: u16`, which is 0–100.

## Git

- Work on a feature branch and open a PR into `master`.
